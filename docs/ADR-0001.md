# ADR-0001: Start with a modular monolith and fail-closed tenancy

Date: 2026-10-21
Status: Accepted for the initial foundation PR

## Decision

Use ASP.NET Core 10 (LTS), PostgreSQL and EF Core 10 in one deployable API, with
feature directories to allow future extraction. Use signed OAuth2/OIDC JWTs from
an independently managed identity provider. API endpoints must validate both a
tenant claim and a current tenant membership stored server-side. Tenant data is
partitioned by tenant UUID; ORM filters apply by default; application writes
must assert tenant identity. Keep deployment access to PostgreSQL private.

## Trade-offs

- No in-house JWT signing, test-token bypass or unauthenticated tenant selection.
- PostgreSQL RLS and verified integration tests should supplement ORM filtering
  before customer data is processed. ORM query filters alone are not a complete
  security boundary, especially around raw SQL.
- Initial SQL script is **not** a production migration strategy. Move to reviewed,
  versioned migrations before shipping.
- Rate limiting is process-local; use distributed tenant-aware quotas when scaling.
- No asynchronous queue, cache or vector index until a measured workload
  demands it. Avoid operational costs of premature microservices.

## Adding a new feature

1. Inspect main, recent commits, open PRs and this status document.
2. Propose exactly one reviewable vertical slice on a new branch.
3. Identify authentication, tenant, input and secret handling risks.
4. Add relevant tests and CI; record limitations, rollout and rollback.
5. Merge only when the branch passes checks and review.
